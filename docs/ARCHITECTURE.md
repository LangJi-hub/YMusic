# 架构说明

本文记录几个关键设计决策的**原因**，避免后来者「看起来能简化」就动手改掉。

## 1. 运行形态：脚本态与打包态

同一份 `server.mjs` 要跑在两种环境里：

| 形态 | 入口 | `__dirname` 指向 |
|---|---|---|
| 脚本态 | `node server.mjs` | 源码所在目录 |
| 打包态 | Node SEA 单文件 | **虚拟路径**（不可写） |

因此所有可写路径必须经 `APP_DIR`：

```js
const APP_DIR = process.env.YM_APP_DIR
  || (IS_SEA ? path.dirname(process.execPath) : __dirname);
```

打包态下配置、日志、数据目录都落到**可执行文件所在目录**，用户把 exe 拖到哪儿，数据就在哪儿。

### 探测方式为什么不用顶层 await

```js
const nodeRequire = createRequire(import.meta.url);
let SEA = null;
try { SEA = nodeRequire('node:sea'); } catch { SEA = null; }
```

SEA 的 ESM 引导对顶层 `await import()` 支持不稳，曾导致打包产物启动即崩。改用 `createRequire` 同步探测后稳定。

### 前端资源解析顺序

`磁盘优先 → 读不到则读内嵌资产`。这样开发时改 HTML 刷新即可（不用重打包），发布时资源已内嵌（单文件分发）。

## 2. 服务端：单文件的分层

14,600 行不是一坨。内部分层清晰：

```
常量与运行形态探测
        ↓
工具层：writeJSON / 原子写 / HTTP 客户端 / 错误包装
        ↓
存储层：DATA_DIR 下各 JSON 的读写与热更新
        ↓
音源适配层：kg* / qq* / ne* / dy* / bili* 前缀函数
        ↓
业务层：检索、播放、下载、账号、社交
        ↓
路由层：pathname 分发（152 个端点）
```

**不允许**在服务端 `import` 任何第三方包或本地模块文件——SEA 只注入这一个文件，引外部模块会在打包态直接崩。

## 3. 音源适配层

每个平台一套独立函数族，统一收敛到三个动作：

| 动作 | 说明 |
|---|---|
| 搜索 | 走各平台公开检索接口，结果做字段归一 |
| 解析 | 拿播放地址，按音质逐档探测 |
| 凭证 | 登录态维护（Cookie 池、设备指纹、到期处理） |

以网易云为例，函数族以 `ne` 为前缀：`neWeapi`（接口签名）、`neDeviceCookie`（设备 Cookie）、`neCookieMerge`（Cookie 合并）、`neProbeLevels`（音质探测）、`neVipInfo`（会员信息）、`neSaveHealth`（健康落盘）。

### 设备 Cookie 为什么必须带

网易云对「新设备」只给 30 秒试听。实测同一账号：带完整 Cookie 链可出 53MB，只带 `MUSIC_U` 仅 720KB。所以 `NMTID` / `_ntes_nuid` 这类设备标识必须收全。

### 音质为什么要逐档实测

接口自报的码率不可信——它按账号权限「声称」能给什么，实际请求常常降级或返回试听片段。因此采取「请求一档 → 校验实际字节与时长 → 不行降一档」的策略，宁慢不错。

## 4. 认证与会话

- 密码：`scrypt` + 每用户随机盐，存 `scrypt$<salt>$<hash>`
- 会话：令牌存 `sessions.json`，TTL 90 天
- 票据：一次性访问凭据，密钥存 `secrets.json`，与 SMTP 配置同文件，复用同一套原子写

`userOf()` 返回 `{ uid, user, token }` 包装对象而非账号本体——调用方容易误把它当账号用，改签名要连带检查所有消费点。

## 5. 存储层

选择 JSON 而非数据库的理由见 README。这里只强调**写入必须原子**：

```js
// 先写临时文件，再 rename 覆盖
writeJSON(file, obj)  // 进程被杀也不会留下半截 JSON
```

`secrets.json` 按 `mtime` 热更新：内存有则用内存，内存没有再读盘。这样改配置不用重启服务。

## 6. 前端：单文件 + ES5

`web/index.html` 29,600 行，包含样式、结构、全部逻辑。视图通过容器切换：

```
home · search · rank · special · singer · fav · history · tasks · me · settings
```

### ES5 约束的真实原因

不是为了兼容而兼容。目标设备包括老车机、电视浏览器、低版本安卓 WebView、以及 Electron 注入环境。这些环境对新语法支持参差，**一处语法错误 = 整页白屏**。

禁用清单：`let` / `const` / 箭头函数 / 模板字符串 / 解构 / `class` / 可选链 / 展开运算符。

### 单文件的两个已知陷阱

1. **编辑容易破坏括号配对**。体量大，`old_string` 很容易把相邻分支的 `if/else/}` 一起吃进去，结果是整块脚本不执行、页面全黑，而静态检查（版本门禁、规则检查）全部通过——它们查的是「有没有违规写法」，不查「还是不是合法 JS」。**改完必须跑语法检查。**
2. **列表数据源三处耦合**。新增一个可播放列表，必须同时改：容器选择器、上下文目标映射的白名单、该分支的数据源指向。漏掉第三处会静默播错歌（落进默认分支拿上一次的搜索结果），比不播更难查。

## 7. 为什么是两个管理台

`web/admin.html` 与 `admin/` 是**两个不同产品**，接口面零重叠：

| | 运营管理台 | 账号管理台 |
|---|---|---|
| 进程 | 主服务内 | 独立进程 `:8803` |
| 使用者 | 管理员（手机 / 桌面 / 网页） | 运维与开发者 |
| 职责 | 审核、公告、角色、白名单 | 数据归集、去重、备份恢复、发布打包 |
| 接口 | `/api/admin/*` | `/api/state`、`/api/users`、`/api/merge`… |

合并会让「运营人员提权即可操作备份恢复」变成现实，所以刻意拆开。**不要把两者合并。**

## 8. 部署拓扑

```
公网 → 反向代理（HTTPS，建议 Nginx）
         → 127.0.0.1:8788   主服务
         → 127.0.0.1:8803   账号管理台（只在运维时开）
```

应用本身不处理证书，也不应直接监听公网地址。`install.sh` 默认装 systemd 单元托管两个进程。

## 9. 数据目录

```
data/
├── users.json        账号（含 scrypt 哈希）
├── sessions.json     会话
├── secrets.json      SMTP 授权码 / 票据密钥 / 平台凭证  ← 按密钥对待
├── social.json       关注 / 好友 / 分享
├── moments.json      动态
├── listen.json       一起听房间
├── *-health.json     平台凭证健康
└── daily-cache.json  每日推荐缓存
```

备份 = 复制 `data/` + `Downloads/`。恢复 = 放回原位。**这两样都不要进版本库。**
